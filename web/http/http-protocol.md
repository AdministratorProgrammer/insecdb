**HTTP (HyperText Transfer Protocol)** - это фундаментальный протокол прикладного уровня, лежащий в основе передачи данных в World Wide Web. Он определяет, как клиенты (например, браузеры) и серверы обмениваются информацией, и с момента своего создания стал основой для большинства сетевых взаимодействий.

### Основа: Архитектура «Клиент-Сервер» и модель «Запрос-Ответ»

HTTP построен на простой модели **«запрос-ответ»** (request-response) в рамках архитектуры «клиент-сервер».

1.  **Клиент** (например, браузер) инициирует соединение с сервером и отправляет **HTTP-запрос**.
2.  **Сервер** обрабатывает запрос и возвращает **HTTP-ответ**, содержащий запрошенный ресурс или информацию о статусе операции.
3.  После отправки ответа сервер обычно закрывает соединение, хотя современные версии протокола позволяют сохранять его для повторного использования (**[[keep-alive]]**).

Ключевая характеристика HTTP - он **не хранит состояние** (stateless). Это означает, что сервер не сохраняет никакой информации о предыдущих запросах клиента. Каждый запрос обрабатывается независимо, что упрощает масштабирование системы, но требует дополнительных механизмов (например, [cookie](cookie-and-http.md)) для реализации функций, которым нужно помнить пользователя, таких как аутентификация.

### Анатомия HTTP-сообщения

Любое HTTP-сообщение (будь то запрос или ответ) состоит из трёх частей:
*   **Стартовая строка**: Для запроса - это метод, URI и версия протокола. Для ответа - версия протокола, код состояния и его текстовое описание.
*   **Заголовки (Headers)**: Метаданные, передающие дополнительную информацию о сообщении, клиенте, сервере или ресурсе.
*   **Тело (Body, Payload)**: Необязательная часть, содержащая сами данные (например, HTML-код страницы, данные формы или файл). Тело может отсутствовать, например, в ответах на запросы `GET` или `HEAD`.

### Методы HTTP-запросов

Метод определяет, какое действие клиент хочет выполнить над указанным ресурсом. Вот основные из них:

| Метод       | Назначение                                                                                                                                                                                 |
| :---------- | :----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **GET**     | **Получение** данных. Самый распространённый метод, используемый для запроса веб-страниц, изображений и т.д. Не должен изменять состояние на сервере.                                      |
| **HEAD**    | Идентичен `GET`, но сервер возвращает **только заголовки**, без тела ответа. Используется для проверки существования ресурса или получения его метаданных без загрузки самого содержимого. |
| **POST**    | **Отправка** данных на сервер для обработки. Часто используется для отправки форм, загрузки файлов или создания новых ресурсов.                                                            |
| **PUT**     | **Полная замена** существующего ресурса данными из запроса. Если ресурс не существует, может создать его.                                                                                  |
| **DELETE**  | **Удаление** указанного ресурса.                                                                                                                                                           |
| **OPTIONS** | Возвращает информацию о **коммуникационных опциях** для ресурса (например, какие методы поддерживаются).                                                                                   |
| **PATCH**   | **Частичное изменение** ресурса. В отличие от `PUT`, который заменяет ресурс целиком, `PATCH` применяет изменения только к его части.                                                      |

### Коды состояния HTTP-ответов

Код состояния - это трёхзначное число, которое сообщает клиенту результат обработки его запроса. Все коды делятся на пять классов:

| Класс | Значение | Описание |
| :--- | :--- | :--- |
| **1xx** | **Информационный** | Запрос получен, процесс обработки продолжается. |
| **2xx** | **Успех** | Действие было успешно получено, понято и принято. (Например, `200 OK`, `201 Created`). |
| **3xx** | **Перенаправление** | Для завершения запроса необходимо предпринять дальнейшие действия. (Например, `301 Moved Permanently`, `304 Not Modified`). |
| **4xx** | **Ошибка клиента** | Запрос содержит синтаксическую ошибку или не может быть выполнен. (Например, `404 Not Found`, `403 Forbidden`, `401 Unauthorized`). |
| **5xx** | **Ошибка сервера** | Сервер не смог выполнить корректный запрос. (Например, `500 Internal Server Error`). |

### Заголовки HTTP

Заголовки передают важные метаданные и делятся на категории:
*   **Заголовки запроса**: Передают информацию о самом запросе и клиенте. Примеры: `User-Agent` (информация о браузере), `Accept` (какие типы контента клиент может принять), `Host` (доменное имя сервера).
*   **Заголовки ответа**: Передают информацию об ответе и сервере. Примеры: `Content-Type` (тип данных в теле ответа), `Server` (информация о серверном ПО), `Set-Cookie` (устанавливает cookie на клиенте).
*   **Заголовки сущности**: Описывают тело сообщения. Примеры: `Content-Length` (размер тела в байтах), `Content-Encoding` (метод сжатия, например, gzip).

### Версии протокола: Эволюция производительности

Семантика HTTP (методы, коды, заголовки) остаётся единой, но его транспортный уровень развивался для повышения скорости и эффективности.

*   **HTTP/1.1**: Долгое время был стандартом. Использует текстовый формат для передачи сообщений и, как правило, одно TCP-соединение для каждого запроса. Для загрузки страницы с множеством ресурсов браузеру приходится открывать несколько параллельных соединений, что создаёт дополнительную нагрузку.
*   **HTTP/2**: Главное нововведение - **мультиплексирование**. Оно позволяет передавать несколько запросов и ответов одновременно по одному TCP-соединению. Это достигается за счёт бинарного формата и разбиения сообщений на кадры (framing layer), что значительно ускоряет загрузку страниц.
*   **HTTP/3**: Самое радикальное изменение. Вместо TCP он использует новый транспортный протокол **QUIC**, который работает поверх UDP. QUIC решает проблему «блокировки начала очереди» (head-of-line blocking), присущую TCP, и обеспечивает более быстрое установление соединения и лучшую производительность в сетях с потерями пакетов.

### Безопасность: HTTPS

**HTTPS** - это не отдельный протокол, а расширение HTTP, которое использует шифрование для защиты передаваемых данных.

*   **Как это работает**: HTTPS «оборачивает» обычный HTTP-трафик в протокол шифрования **TLS** (Transport Layer Security) или его предшественника **SSL**.
*   **Что это даёт**:
    *   **Конфиденциальность**: Данные шифруются, что защищает их от перехвата и прочтения злоумышленниками (например, пароли или номера банковских карт).
    *   **Целостность**: Гарантируется, что данные не были изменены при передаче.
    *   **Аутентификация**: С помощью цифровых сертификатов клиент может убедиться, что он общается с легитимным сервером, а не с поддельным.

### Кэширование

Кэширование - это механизм, позволяющий клиенту (браузеру) или промежуточному серверу (прокси, CDN) сохранять копии ресурсов и повторно использовать их, сокращая время загрузки и снижая нагрузку на сервер.

Ключевые заголовки для управления кэшем:
*   **`Cache-Control`**: Основной заголовок, определяющий правила кэширования (например, `max-age` указывает, как долго ресурс считается «свежим»).
*   **`ETag`**: Уникальный идентификатор версии ресурса. Клиент может отправить его в запросе (`If-None-Match`), чтобы проверить, изменился ли ресурс на сервере. Если нет, сервер вернёт код `304 Not Modified` и ресурс не будет загружен повторно.
*   **`Last-Modified`**: Дата и время последнего изменения ресурса. Работает аналогично `ETag`, но на основе времени.
